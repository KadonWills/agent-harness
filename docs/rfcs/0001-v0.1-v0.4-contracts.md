# RFC-0001: Contracts for v0.1–v0.4 (gate, eyes, referee, shield)

- Status: Accepted
- Author(s): @KadonWills (agent-assisted, see PR)
- Tracking issue: —

## Summary

Define every public-contract change needed to ship roadmap milestones v0.1
("The Gate") through v0.4 ("The Shield") in one place, so the implementation
PRs that follow can each point at an accepted design instead of each opening
their own RFC. Covered: the `harness.toml` schema, `AgentManifest.json`, the
`LanguageParser` and `SandboxBackend` traits, the CLI surface and exit codes,
one new crate (`harness-security`), and an MSRV bump.

## Motivation

The scaffold defines contracts that are too small to implement the PRD:

- `harness run` must execute *the project's* validation commands, but the
  config has nowhere to put them, nor a container image, nor a time limit.
- `SandboxBackend::run(config, command)` runs one command and has no notion
  of a workspace snapshot, setup phase, or wall-clock budget.
- `AstChange` cannot express a rename, a removed type member, or a new
  reference — the three facts the PRD's schema-drift scenario (§4.4) needs.
- The manifest has no verdict, no step results, and no place for egress,
  secret, dependency, or conflict findings (§4.5, §4.7).

## Design

### 1. `harness.toml`

All new fields default safely; an empty file stays valid and zero-trust.
Unknown fields remain hard errors. Durations are `<int><unit>` with unit
`s`, `m`, or `h`; memory sizes are `<int><unit>` with unit `KB`, `MB`, `GB`
(case-insensitive, binary multiples).

```toml
[project]
name = "core-api"
base_ref = "main"                 # NEW. Ref `harness run` diffs against.

[sandbox]
provider = "docker"               # "docker" | "wasmtime"
allow_egress = false
max_memory = "512MB"
image = "node:22-bookworm-slim"   # NEW. Docker image. Default "debian:bookworm-slim".
timeout = "10m"                   # NEW. Wall-clock budget for the whole session.
max_cpu_time = "5m"               # NEW. Per-process CPU-time ceiling (RLIMIT_CPU).
allow_setup_egress = false        # NEW. Network for [validation].setup only.

[validation]                      # NEW section
setup = ["npm ci"]                # run first; may get network (see above)
commands = ["npm test"]           # always run with egress per allow_egress

[agents]
allowed = ["claude-code"]
strict_mode = true

[conflicts]                       # NEW section
branches = ["agent/*"]            # sibling-branch globs compared on every run

[security]                        # NEW section
scan_secrets = true               # default true
secret_rules = ""                 # optional gitleaks-format TOML, merged with built-ins

[security.dependencies]           # NEW section
allow = []                        # globs; when non-empty, new deps must match
deny = []                         # globs; matching new deps are blocked
typosquat_check = true            # default true
advisory_db = ""                  # optional path to a directory of OSV JSON files
```

`harness init` writes `image`, `setup`, `commands`, and
`allow_setup_egress = true` for the detected ecosystem, with a comment that
names the trade-off. The *default* stays `false`, so an empty or hand-written
config never grants network implicitly.

### 2. `AgentManifest.json`

`manifest_version` stays `"1"`: every change is additive, and every new field
deserializes with a default so manifests from scaffold builds still parse.

New top-level fields:

| Field | Type | Meaning |
|---|---|---|
| `verdict` | `"Pass" \| "Blocked" \| "Unknown"` | The gate decision. `Unknown` only appears when reading an older manifest. |
| `blocking_reasons` | `string[]` | One agent-legible sentence per reason the gate blocked. |
| `base_ref`, `head` | `string` | What was diffed: the base ref and the HEAD commit SHA. |
| `steps` | `StepReport[]` | `{phase: "setup"\|"validate", command, exit_code, duration_ms, timed_out}` |
| `conflicts` | `ConflictReport[]` | `{level: 1\|2, kind, symbol, branches: [a, b], explanation, fix}` (`fix` nullable) |

`security_audit` gains `egress_events`
(`{step, destination, evidence}`), `secret_findings`
(`{rule_id, description, path, line}` — the secret itself is never written),
and `dependency_findings` (`{ecosystem, name, file, reason}`). The existing
counters stay and equal the lengths of the matching lists.

`impacted_files[].ast_changes` stays `string[]`; each entry is
`<Variant>:<symbol>` (for example `FunctionChanged:resolveUser`,
`MemberRemoved:User.email`). `ReferenceAdded` events are conflict-engine
input and are not written to the manifest.

`intent_hash` is the SHA-256 (hex) of the instruction text after trimming
and collapsing whitespace, or `""` when no intent was supplied.

### 3. `LanguageParser` and `AstChange`

The trait signature is unchanged. `AstChange` becomes `#[non_exhaustive]` and
gains variants:

```rust
FunctionRenamed { from: String, to: String }  // identical body, new name
SignatureChanged(String)                      // parameters/return type differ
TypeAdded(String), TypeRemoved(String)
MemberRemoved { owner: String, member: String }
ReferenceAdded(String)                        // identifier newly referenced
```

Symbols nested in a type are qualified (`User.save`). Parsers are built from a
shared Tree-sitter walker plus a per-language mapping table, which is what
keeps a new language under 100 lines.

### 4. `SandboxBackend`

Replaced (pre-1.0, no external implementors yet):

```rust
pub trait SandboxBackend: Send + Sync {
    fn name(&self) -> &'static str;
    /// Ok when usable; Err says what is missing and how to fix it.
    fn check_available(&self) -> Result<(), Error>;
    /// Run setup then validation commands against a prepared snapshot.
    fn execute(&self, plan: &ExecutionPlan) -> Result<SessionReport, Error>;
}
```

`ExecutionPlan` carries the snapshot directory, setup and validation
commands, limits (memory bytes, CPU time, wall-clock timeout), egress flags,
and the image. `SessionReport` returns per-step outcomes (with captured
output) and detected egress events. Execution stops at the first failing
step; the session's wall-clock budget is shared by all steps.

Egress auditing in the Docker backend is a deterministic scan of step output
for resolver/connect failure signatures (`getaddrinfo ENOTFOUND host`,
`Could not resolve host: host`, …). It records destination and originating
step. It cannot see attempts that a program swallows silently; that limit is
documented, and a packet-level audit is future work.

The Wasmtime backend runs WASI (preview 1) modules: each command's first
word is a `.wasm` path relative to the repository. The snapshot is the only
preopened directory, and WASI exposes no sockets, so egress is impossible
rather than merely denied.

### 5. CLI

| Command | Purpose |
|---|---|
| `harness init [--force] [--hooks]` | Write `harness.toml` for the detected ecosystem; `--hooks` installs pre-commit and pre-push hooks (also works when the config already exists). |
| `harness check [--json]` | Validate config and backend availability. |
| `harness run [--agent ID] [--intent TEXT \| --intent-file PATH] [--base REF] [--manifest PATH] [--json]` | The full gate. Default manifest path `.harness/AgentManifest.json`. |
| `harness scan [--staged \| --base REF] [--json]` | Secret and dependency gate only, no sandbox. The pre-commit hook runs `harness scan --staged`. |
| `harness conflicts [--base REF] [--fix] [--json] [BRANCH...]` | Cross-branch semantic conflicts. With no branches, uses `[conflicts].branches`. `--fix` applies Level 1 codemods to the checked-out working tree only. |

`--agent` and the intent flags fall back to `HARNESS_AGENT` and
`HARNESS_INTENT`.

Exit codes, for every command:

| Code | Meaning |
|---|---|
| 0 | Pass / nothing found |
| 1 | The gate blocked (failed step, finding, Level 2 conflict, `check` problem) |
| 2 | Harness could not run (invalid config, git or backend error, bad usage) |

### 6. Conflict rules (v0.3)

For each ordered pair of change sets (A, B):

| Rule | Level | Fires when |
|---|---|---|
| removed-symbol | 2 | A removes function/type `x`; B newly references `x` and does not define it |
| removed-member | 2 | A removes member `T.m`; B newly references `m` and does not define it |
| signature-change | 2 | A changes the signature of `x`; B newly references `x` |
| concurrent-edit | 2 | A and B both change symbol `x` in the same file |
| renamed-symbol | 1 | A renames `x`→`y`; B newly references `x`. Fix: rewrite B's identifier references (skipped if B's file declares `x`). |
| lockfile | 1 | A and B both modify the same lockfile. Fix: regenerate after merge (command suggested, never run). |

The rules are name-based and deliberately conservative. A false positive
costs a human glance; a silent false negative is what the tool exists to
prevent.

### 7. New crate: `harness-security`

Secret scanning (gitleaks-compatible rule subset: `id`, `description`,
`regex`, `secretGroup`, `entropy`, `keywords`, `path`, allowlist `regexes` /
`stopwords`, plus `gitleaks:allow` / `harness:allow-secret` inline markers)
and dependency policy (manifest extraction for npm, PyPI, Cargo, Go; deny /
allow globs; offline typosquat check against bundled popular-package lists;
offline OSV advisory match on exact pins and whole-package `MAL-` entries).
It depends only on `harness-core`. Commit/PR scope: `security`.

### 8. MSRV

Current Tree-sitter (`tree-sitter-language` 0.1.9) requires Rust 1.90, so
the MSRV for **default features** moves from 1.75 to 1.90, in the PR that
first adds Tree-sitter. Wasmtime tracks the latest stable compiler (49.x
requires 1.96), so the opt-in `wasmtime` feature is exempt: it follows
Wasmtime's own MSRV, and the CI MSRV job checks default features only.

## Alternatives considered

- **One RFC per milestone.** Cleaner in isolation, but the milestones share
  the manifest and config; four RFCs would amend each other.
- **Bump `manifest_version` to `"2"`.** Rejected: every change is additive,
  and a version bump forces consumers to branch for no reason.
- **`bollard` (Docker API client) instead of the `docker` CLI.** Pulls in an
  async runtime and a large tree; the CLI is the boring, debuggable path and
  is what users already have.
- **Online advisory lookups (OSV API).** Breaks determinism and air-gapped
  use (ADR-0004). Users who want fresh data download an OSV snapshot and
  point `advisory_db` at it.

## Compatibility

- `harness.toml`: additive; existing files parse unchanged.
- `AgentManifest.json`: additive; `manifest_version` stays `"1"`.
- `LanguageParser`: signature unchanged; `AstChange` gains variants and
  becomes `#[non_exhaustive]` (breaking for exhaustive matches — no external
  implementors exist yet).
- `SandboxBackend`: replaced; no external implementors exist yet.
- CLI: new commands and flags; the exit-code table above becomes the
  contract.

## Unresolved questions

- OQ-1 (worktree layout) is sidestepped: v0.3 compares branches via git,
  not worktrees. Worktree-per-session can be layered on later.
- OQ-3 (Windows sandbox): Docker Desktop or the Wasmtime backend; no
  Windows-native process sandbox is attempted.
